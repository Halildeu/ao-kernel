## 1. Context

GPP-2D-3c (PR #599, squash commit `a4a0070`) retired the GPP-2D-2c
advisory shadow workflow in favor of a single enforce job inside
`.github/workflows/test.yml` under the reserved required-check name
`ao-release-gate`. Two follow-on slices landed on top:

  * PR #601 (squash `5e53065`) extended the trusted-base builder's
    `DEFAULT_ALLOWED_PATH_PREFIXES` with the two repo-root evidence
    file names the enforce job legitimately needs in scope
    (`local-ai-review-evidence.v1.json` and
    `local-gpp-gate-evidence.v1.json`). The ao-release-gate enforce
    job did NOT exist on PR #601's base ref, so PR #601's own CI
    run is bootstrap-chain context — not enforce-mode evidence.
  * PR #602 (squash `28d4348`) narrowed the workflow's inline
    comment above `git check-ref-format refs/heads/$REF` to match
    the evidence-file wording and documented the actual
    option-injection-safety rationale.

This document collects the ao-release-gate enforce-mode evidence
those PRs generated on their `Test / ao-release-gate
(pull_request)` runs. It does not mutate branch protection;
GPP-2D-5 is the separate operator slice that makes
`ao-release-gate` a required status check with admin bypass
disallowed.

## 3. Negative evidence

The enforce contract requires `--conclusion-mode enforce` +
`--fail-on-deny`, so every non-`allow_autonomous_merge` decision
must exit the job with code 1. The chain below is the natural
failure surface PR #599's review iterations and PR #602's initial
stale-evidence state generated. All rows are runs of `Test /
ao-release-gate (pull_request)`.

### 3.1 `decision: deny_policy_violation` (`diff_scope: blocked`)

| Run id        | PR    | Head SHA  | Cause                                                   |
|---------------|-------|-----------|---------------------------------------------------------|
| `26363656150` | #599  | `1fcb5d1` | Iter-4 absorb head, BEFORE PR #601 bootstrap-prep merged. The new `local-ai-review-evidence.v1.json` file at the repo root was not yet in `DEFAULT_ALLOWED_PATH_PREFIXES`, so `diff_scope: blocked` with finding `ao_release_gate_diff_out_of_scope`. `review_evidence: pass` and `review_evidence_context_bound: pass` confirm the reviewer evidence path was actually intact — the deny is purely a path-allowlist issue. |
| `26363317617` | #599  | `b0db5a1` | Iter-3 absorb head, same bootstrap gap. The trusted-base ref-binding step (`git check-ref-format` + `git update-ref`) ran, but the trusted-base allowlist still lacked the reviewer evidence file. `review_evidence: pass`, `review_evidence_context_bound: pass`, only `diff_scope` blocked. |

Coverage: confirms the decision core's `diff_scope` check rejects
out-of-allowlist paths in enforce mode and reports
`ao_release_gate_diff_out_of_scope` as the finding code, exiting
1 in enforce mode regardless of whether reviewer evidence is
otherwise present and accepting.

## 4. Coverage summary

The enforce-mode contract `ao-release-gate` enforces is:

  1. **Trusted-base discipline** — decision core / schemas /
     `gpp_status.v1.json` / `scripts/local_gpp_gate.py` are loaded
     from the PR base SHA, never the head. **Exercised** by every
     row in §2 and §3. Rebasing PR #599 onto the new main after
     PR #601 merged is what flipped its outcome from
     `deny_policy_violation` to `allow_autonomous_merge` without
     changing its head diff.
  2. **Reviewer evidence committed at the PR head, schema-valid,
     verdict=AGREE, cross-provider implementer != reviewer.**
     **Exercised** by §3.2 (missing / stale variants), §3.1
     (present and accepting but diff out of scope), and §2
     (present, accepting, in scope).
  3. **Runtime gate-evidence generated by
     `base/scripts/local_gpp_gate.py`** against the PR-head
     reviewer evidence + the actual git diff. **Exercised** by
     the §2 positive rows (the file is part of the canonical
     4-file artifact set) and by `26362713579` (where the
     runtime step failed and the artifact set is degraded to 3
     files).
  4. **Fully-qualified ref invocation (`--base-ref
     refs/heads/$BASE_REF` etc.) plus the upstream
     `check-ref-format` + `update-ref` binding step.**
     **Exercised** by `1fcb5d1` (iter-4 absorb, the commit that
     introduced the fully-qualified contract), `e7c95aa`
     (positive run after rebase), and `958a8d8` (PR #602
     positive run). Earlier iter-2/iter-3 absorb runs
     (`552aa33`, `b0db5a1`) exercised the prior contract
     variants — branch-label legacy alias only, and branch-label
     + `update-ref` without the fully-qualified invocation — and
     are recorded in §3 as the negative examples that motivated
     the iter-4 fix.
  5. **`--conclusion-mode enforce` + `--fail-on-deny` exit-1
     behavior.** **Exercised** by every red row in §3 — the
     `gh run view --log-failed` output for each shows
     `Process completed with exit code 1` after the `Evaluate
     ao-release-gate decision (enforce)` step.
  6. **`if: always()` audit artifact upload.** **Exercised** by
     every row in §2 and §3. The positive rows uploaded the full
     4-file artifact set (payload / decision / runtime evidence
     / local-gpp-gate stdout log); the §3 rows uploaded whatever
     subset existed at the moment the synthesizer ran. The
     `26362713579` row's degraded 3-file upload (no runtime
     evidence) is the canonical example that the contract holds
     even when an earlier step crashes mid-way.
